# MAA MHXY Web 中控（同机多模拟器）

此版本基于 gitlihang/Maa_MHXY_MG 上游提交 `722d023`，增加独立的 Python Web 服务与中文浏览器控制台。原桌面版入口仍可使用。Web 服务必须运行在安装模拟器、能够通过 ADB 连接设备的电脑上。

## 已实现

- 扫描本机 ADB 模拟器，或手动添加地址；按名称、地址搜索，筛选运行中或异常实例。
- 每个实例独立保存名称、任务配置选择和任务参数；可调整执行顺序。
- 从上游 `assets/interface.json` 及导入文件读取全部 37 个任务和 25 个选项。支持开关、下拉、多选、输入、分支下的嵌套选项，以及整数转换、正则校验。
- 仅使用官方客户端配置；界面无需选择或显示游戏资源包。
- 单实例启动/停止、多选批量启动/停止；同一实例不允许重复执行，运行时不允许修改或删除配置。
- 显示运行状态、当前任务、队列进度和日志（每 2 秒轮询）；按需刷新设备 PNG 截图。
- 每次运行独立 MaaFramework 执行进程和原项目自定义 Agent；原来的识别器、动作、分辨率检查器均接入。
- 每个实例的自定义状态文件单独保存，跨次运行保留；每次运行的原生和自定义日志分别存放。
- 默认允许局域网免令牌访问，打开页面直接进入控制台；页面禁用跨域请求。

## 组合任务并保存为可复用配置

1. 左侧点击「任务配置」→「新建配置」，填写名称。
2. 在任务库中勾选多个任务，点击「加入队列」；也可点击任务旁的加号单独添加。
3. 在执行队列中调整顺序，展开并设置各个任务的开关、输入和嵌套选项，然后点击「保存配置」。
4. 回到「模拟器总览」，在每个实例卡片的「任务配置」下拉框中直接选择已保存配置，点击启动即可执行。
5. 同一配置可以被多个实例选用。配置列表可查看使用实例，并支持编辑和复制；复制后的组合可独立修改。

配置包含任务顺序和任务参数，实例名称仍可通过卡片右上角设置按钮修改。选择「请选择任务配置」会取消任务配置；未选择配置时不能启动配置。

共享配置更新后，所有引用它的实例在下次启动时使用新版。正在执行的队列保存了启动时的任务快照，不受后续修改影响。实例运行中不能切换配置。正在被实例引用的配置不能删除，需先到实例卡片切换或取消选择。

升级前在实例上单独配置的任务会自动迁移为命名配置，保留顺序及选项；内容相同的组合会复用同一配置，空队列不迁移。旧版每实例任务配置 API 仍兼容，调用它会切换为该实例的独立任务。

## 任务库两级目录

一级为「个人日常、组队日常、周常、日常功能、养成服务」，二级是具体任务。分类可折叠，默认展开个人日常；支持分类全选或单项勾选，所有选中项统一加入右侧执行队列。一个任务配置可以跨分类组合任务，切换目录不会丢失勾选。

搜索会跨所有分类查找并自动展开匹配目录。分类只用于整理任务，不改变已保存组合的顺序、参数或原任务行为。分类归属可根据后续使用反馈再调整。

## 开关机、启动配置和任务进度

实例右上角开关反映 MuMu 的实际开关机状态。打开开关后，等待 Android 就绪并自动打开官方梦幻西游客户端；关闭开关会先停止此实例的任务，再关闭对应 MuMu 实例。其他实例不受影响，不会删除任何 MuMu 实例或游戏数据。

下方按钮为「启动配置」。需要先选一份已保存的配置；执行中按钮变为「停止配置」，仅停止任务而保留模拟器。已有的任务和配置升级后统一使用官方客户端，界面不再显示资源包选择或标签。

进度分为两层：配置队列的第 N/M 项，以及当前游戏任务内部的进度。执行器从游戏右侧任务栏做只读 OCR，显示实际任务文字；识别到当前任务的 3/10 等数字时，再显示对应进度条。没有读到数字时不估算百分比。OCR 随任务节点采样，最短间隔 5 秒；任务长时间等待时刷新也会延后，页面会标注旧识别结果的时间，同时显示当前执行步骤。

左侧「账号中心」已增加独立入口，目前为待完善页面，未实现账号保存、登录或其他操作。

## 版本与更新

左侧「本机执行引擎」会显示两个版本：

- 内核：当前安装的 MaaFramework（`MaaFw`）版本，鼠标悬停可看 `requirements.txt` 要求的版本是否一致；
- 项目：当前检出对应的上游版本标签（如 `v3.0.15`），本地有未提交改动时会标注「本地修改」。

点击「检查更新」会 `git fetch` 上游仓库并对比最新标签，弹窗里显示当前版本、最新版本和更新说明：

- 「立即更新」执行 `git pull --ff-only`，把项目快进到最新版本；本地改动会被保留（与上游改动的文件不重叠时），更新完成后需要重启服务；
- 勾选「发现新版本时自动更新」后，每次打开控制台会在后台检查并自动更新，更新结果用右下角提示；
- 离线或无法访问 GitHub 时会在弹窗里提示原因，不影响其它功能。

## 活动日志（运行回放）

左侧「活动日志」按时间倒序列出每次运行：

- 每次运行从几点开始、几点结束、总用时；
- 每个任务单独的开始时间、耗时和状态（完成 / 失败 / 进行中 / 未执行）；
- 失败运行会显示失败原因；进行中的运行实时更新「已运行」时长；
- 顶部可按实例和状态（全部 / 已完成 / 失败 / 进行中）筛选。
- 标记「疑似空跑」：任务耗时不到同名任务历史中位数的一半，且历史中位数 ≥ 3 分钟；
- 标记「疑似卡住」：同一任务已连续进行超过 10 分钟（不会自动停止，需要时手动停止实例）。

记录保存在 `.web-data/activity/<运行 ID>.json`，最多保留最近 400 次；完整日志仍在 `.web-data/runs/` 下。

## MuMu 实例直接导入与一键启动（macOS）

本机安装 MuMuPlayer for Mac 后，可直接读取多开器已有实例（包括未启动的实例）：

1. 网页点击「添加模拟器」，自动显示 MuMu 的实例名称、编号与状态。
2. 点击单个实例的「添加」，或「全部添加」。应用、ADB 路径和端口自动取得。
3. 回到总览，使用实例右上角开关打开 MuMu 并自动进入游戏。选择任务配置后，点击下方「启动配置」，中控会确保 MuMu 和官方游戏客户端就绪，再执行任务。
4. 若需要自动任务，为实例保存任务配置后点击「启动」；中控会先确保 MuMu 就绪，再按队列运行。

**开关机与配置执行是独立操作：开机后自动打开 MuMu 和官方游戏，不执行任务组合；「启动配置」执行所选任务组合。** 导入不会创建、复制、删除或改写 MuMu 实例；重复导入保留已有任务配置。默认查找 `/Applications/MuMuPlayer.app`，其他路径可在导入窗口中填写。

中控使用 MuMu 官方 `mumutool info/open` 命令，ADB 端口取实例报告或该实例的实际配置，不用编号计算端口。扫描时若管理器未运行，会先打开管理器；导入实例不会自动启动 Android。点击启动才会启动对应实例，最多等待 180 秒；随后检查游戏是否安装，打开游戏，并最多等待 60 秒确认游戏在前台且画面为横屏 16:9。游戏统一使用官方客户端 `com.netease.my`。若设备 ADB 未开启，日志会提示启动超时，需要到 MuMu 打开 ADB 后重试。停止任务会取消等待/执行，不关闭 MuMu 实例。

macOS MuMu 已在当前 Mac 的真实实例上验证。Windows 已增加 MuMu 和雷电直接接入；Windows 适配通过模拟命令输出及接口测试，尚未在 Windows 实机运行。

官方命令参考：[MuMu 开发者支持文档](https://www.mumuplayer.com/tw/help/mac/developer-support-function.html)。

## Windows 启动（推荐）

1. 安装 Python 3.10 或以上版本（推荐 3.12），安装时包含 Python Launcher；解压项目到普通可写目录。
2. 双击 `setup-web.bat`。第一次需要联网安装 `requirements-web.txt` 中的依赖。
3. 双击 `start-web.bat`，保持这个终端窗口打开。
4. 浏览器打开 <http://127.0.0.1:8000>，直接进入控制台。
5. 点击「添加模拟器」，选择 MuMu 或雷电，刷新列表后添加实例；可添加未开机实例。找不到安装目录时，展开路径设置填写安装目录或命令行工具完整路径。模拟器内需要开启 ADB；其他模拟器仍可通过「手动 ADB 添加」接入。
6. 在「任务配置」中新建并保存组合，再在实例卡片下拉框中直接选择。
7. 点击「启动」，或勾选多个实例后「批量启动」。在「日志」查看结果，点击画面按钮获取截图。

也可以手动运行：

```powershell
py -3 -m venv .venv-web
.\.venv-web\Scripts\python.exe -m pip install -r requirements-web.txt
.\.venv-web\Scripts\python.exe -m web
```

如果电脑上安装了多个 Python 版本，可把 `py -3` 换成 `py -3.12`。


### Windows MuMu / 雷电直连

- MuMu 支持带 `mumu-cli.exe` 或 `MuMuManager.exe` 的版本；工具可位于安装目录的 `nx_main` 或 `shell`。同目录需要自带 `adb.exe`（兼容 `adb_server.exe`）。读取 `info --vmindex all`，使用实际报告的 ADB 端口，停机端口未知时等开机再连接。
- 雷电支持 `ldconsole.exe`（兼容 `dnconsole.exe`）及同目录 `adb.exe`。使用 `list2` 读取实例；按官方规则以 `5555 + index × 2` 连接本机 ADB。支持常见的 7 列和带分辨率的 10 列输出。
- 自动查找已安装应用的注册表记录及常见 C/D/E 盘目录；自定义位置、便携版可手动指定工具路径，例如 `D:\LDPlayer\LDPlayer9\ldconsole.exe`。
- 导入后在实例卡片选择配置；开关会打开指定实例、等待 Android 就绪、打开官方游戏并执行现有登录流程。「启动配置」再执行任务组合。账号中心、监控中心沿用同一实例 ADB 连接。
- 实例以模拟器类型、工具路径和编号区分。重复导入保留原配置；关机只关闭选中实例。安装目录移动后应重新导入。
- 游戏画面需横屏 16:9，建议在模拟器设置中使用 1280×720；启动时检查实际截图方向，不根据 Android 自然尺寸误判。
- 在 Windows 电脑重新运行 `setup-web.bat` 安装依赖。不要复制 Mac 的虚拟环境或 `.web-data/devices.json`；任务组合可单独备份 `.web-data/profiles.json`，然后在 Windows 重新导入实例并选择配置。
- 局域网访问使用 Windows 电脑 IP 的 8000 端口；若无法连接，检查 Windows 防火墙是否允许 Python 在专用网络接收入站连接。

接口：`GET /api/emulators` 返回服务端平台及支持类型；`POST /api/emulators/discover` 和 `/api/emulators/import` 接收 `kind`（`mumu` / `ldplayer`）、`app_path`，导入另需 `indexes`。原 `/api/mumu/*` 接口保留兼容。

命令参考：[MuMu 官方命令说明](https://mumu.163.com/redirect/nx/function/mumucli/)、[雷电官方命令说明](https://www.ldplayer.tw/support/ldplayer-ldconsole-command-line-developer-guide.html)。

## macOS / Linux 启动

使用 Python 3.10+（推荐 3.12）：

```sh
python3 -m venv .venv-web
.venv-web/bin/python -m pip install -r requirements-web.txt
./start-web.sh
```

macOS/Linux 模拟器需要能够通过 ADB 访问。本次 Web 版本只支持 ADB；PlayCover 仍使用原桌面版入口。MaaFw 的原生库还要求系统和架构有匹配的安装包。

## 手动添加和设备连接

填写模拟器使用的 ADB 可执行文件路径、实例名称和地址，例如 `127.0.0.1:16384`。每个实例应使用不同的实际地址；端口以模拟器设置为准。MuMu 直连实例无需手动填写这些参数。

扫描不到时，先检查模拟器 ADB 开关及端口。必要时在服务电脑上手动运行：

```sh
/path/to/adb connect 127.0.0.1:16384
/path/to/adb devices
```

Windows 中使用对应 `adb.exe` 路径。截图依赖该 ADB 已连接设备；离线时页面会显示错误。任务启动时 MaaFramework 会执行自己的连接流程。

原项目要求游戏横屏且接近 16:9，例如 1280×720。分辨率不匹配时，原 Agent 检查器会停止任务，Web 日志会显示原因。

## 在局域网的浏览器访问

默认监听 `0.0.0.0:8000`，无需令牌。服务电脑仍可打开 <http://127.0.0.1:8000>；同一局域网的电脑或手机打开 `http://服务电脑的局域网IP:8000`，直接进入控制台。`0.0.0.0` 是监听地址，不是手机访问地址；系统防火墙需要允许该端口。



## 数据、日志和停止行为

默认数据目录为项目根目录 `.web-data/`，已加入 Git 忽略规则：

| 路径 | 内容 |
| --- | --- |
| `access-token` | 可选 `--require-token` 模式使用，默认免令牌时忽略 |
| `devices.json` | 设备信息、选中的配置 ID，以及旧版独立任务 |
| `profiles.json` | 命名任务配置、任务顺序、参数、资源包和版本 |
| `instances/<设备ID>/` | 该设备的自定义任务持久状态 |
| `runs/<设备ID>/<运行ID>/web.jsonl` | 当前次运行的带时间日志 |
| `runs/<设备ID>/<运行ID>/custom/` | 原 Agent 自定义日志 |
| `runs/<设备ID>/<运行ID>/` 其他文件 | MaaFramework 原生日志及诊断文件 |

可用 `--data-dir 路径` 修改目录。仅在显式使用 `--require-token` 时启用验证，并可用环境变量 `MHXY_WEB_TOKEN` 设置至少 16 字符的令牌；默认免令牌模式不使用浏览器令牌。

任务选项若填写 AI API 密钥，会保存在本机 `profiles.json`（旧版独立任务在 `devices.json`），原框架诊断日志也可能包含任务参数。分享项目时排除 `.web-data/`，并限制该目录访问；本交付压缩包不含运行数据和凭据。

点击停止后，先向执行器发出 `post_stop()`；15 秒内仍未退出时终止整个执行进程组（Windows 使用 `taskkill /T /F`），包括其自定义 Agent。停止不会关闭模拟器。正常关闭服务也会清理执行进程。

网页日志只保留当前运行最近 2,000 条；历史完整日志留在磁盘。页面刷新、重新登录后仍可看到当前服务进程中的运行状态。服务重启后显示待运行，不自动重跑任务。旧日志不自动删除，可定期清理 `runs/`。

## 开发、验证和接口

```sh
# 开发测试额外依赖
python -m pip install httpx
python -m unittest discover -s tests -v
# 原生集成测试：真实 MaaFramework + 原项目 Agent + 合成画面，不需要模拟器
python -m tests.smoke_native
```

Web 服务通过 `python -m web` 启动，不能使用多 worker 或自动 reload：设备运行状态保存在单个服务进程中。

| 方法和路径 | 用途 |
| --- | --- |
| `GET /api/profiles` | 列出命名配置及选用它的实例 |
| `POST /api/profiles` | 保存新的任务组合 |
| `PUT /api/profiles/{id}` | 编辑组合，可传 `version` 检查并发修改 |
| `POST /api/profiles/{id}/duplicate` | 复制组合 |
| `DELETE /api/profiles/{id}` | 删除未被实例选用的组合 |
| `PUT /api/devices/{id}/profile` | 选用配置，传 `profile_id`；传 `null` 取消任务配置 |
| `PATCH /api/devices/{id}/settings` | 修改实例名称 |
| `PUT /api/devices/{id}/power` | `{ "on": true/false }` 控制 MuMu / 雷电开关机 |
| `GET /api/catalog` | 任务、选项、资源目录 |
| `POST /api/mumu/discover` | 读取 MuMu 实例（可指定 `app_path`） |
| `POST /api/mumu/import` | 导入选中的实例，参数为 `indexes` 数组 |
| `POST /api/discover` | 扫描 ADB 设备（可指定 `adb_path`） |
| `GET /api/devices` | 配置、当前运行状态 |
| `POST /api/devices` | 添加设备 |
| `PUT /api/devices/{id}` | 保存名称、资源包、任务选项 |
| `DELETE /api/devices/{id}` | 移除空闲设备配置 |
| `POST /api/devices/{id}/start` | 执行已选配置；需要时自动启动 MuMu 和官方游戏，未选配置则拒绝启动 |
| `POST /api/devices/{id}/stop` | 停止执行 |
| `POST /api/batch` | `{ "ids": [...], "action": "start或stop" }`，逐个返回结果 |
| `GET /api/devices/{id}/logs?after=0` | 当前运行状态和日志，可按序号增量获取 |
| `GET /api/devices/{id}/screenshot` | 获取设备 PNG 截图 |

默认 `/api/` 请求无需令牌。可选的 `--require-token` 模式才需要请求头 `Authorization: Bearer <访问令牌>`。服务和页面同源，不开放跨域。

## 编组自动组队

在「组队日常」中添加「编组自动组队」，放在配置第一项；后面放队长要执行的副本、捉鬼等任务。五个实例可以选择同一份配置。

- 在队长游戏的好友编组中建立「自动组队」，放入四名队员；队员号不要建立同名编组。
- 编组名默认「自动组队」，等待时间默认 360 秒，可设置 10～1800 秒。
- 队长始终从该编组的联系人列表检查「邀请入队」，未满五名真人时循环邀请，满员连续确认后才执行后续任务。助战不算人数。
- 队员优先识别游戏左侧的邀请弹窗并点击「接受」，跟队时自动确认副本准备。队长配置结束或停止时，中控通知队员结束跟队，后续队长任务记为未执行。
- 相同编组同时出现多个队长、等待超时或界面识别失败会明确报错。邀请范围不扩展到其他好友，不自动匹配陌生玩家，不自动踢人。
- 组队脚本在 MuMu 上使用有超时及重试的 PNG 采集；进度识别和组队窗口识别互相隔离。

个人日常请使用另一份配置；更多说明见 `docs/description/web_auto_team.md`。

## 账号中心

每个已添加的模拟器对应一个切页，可查看独立保存的角色姓名、ID、等级、门派、帮派、帮贡、活力、金币、银币，以及已识别的修炼与帮派技能等级。点击「采集此实例」采集选中的运行窗口；「采集已运行窗口」只处理已开机、未运行任务的实例，不会启动关闭的模拟器。采集按实例排队执行，期间禁止该实例启动任务、切换配置或开关机，请勿手动切换游戏页面。

数据来自游戏画面，按栏目保留采集时间。未识别的数据使用「—」；金币 0 是正常数值，不与未识别混淆。「万/亿」简写的余额显示为约数。识别到角色 ID 或姓名发生变化时会清除上一角色的栏目，避免混用资料；本次某栏目读取失败时可保留上次成功值及原时间，并显示失败说明。

采集仅打开资料、背包和技能页，不进行购买、充值或技能升级。当前运行的小号为 23 级，已实测读取角色资料、金币、银币、活力和帮贡；该窗口的技能页未显示修炼、帮派入口，因此这两项标注为「当前不可采集」，没有填写虚构等级。服务器字段尚未读取。角色快照、采集截图和日志仅保存在 `.web-data/accounts/`，不包含在项目导出包中。


### 登录弹窗与场景确认修复

开机进入游戏时，先处理明确识别到的福利弹窗、月卡每日返利遮罩和带关闭提示的登录公告，再连续三次确认主界面。只在识别到月卡标题和领取本日奖励提示时点击领取位置；未识别的窗口不会尝试通用坐标点击。

实例卡片实时显示登录子进程的阶段。开机成功仅表示模拟器运行；登录失败会保留原因，不会报告已进入场景。诊断位于 `.web-data/logins/<实例ID>/<本次ID>/` 的 `stages.jsonl`、`login-output.log` 和 `last-screen.png`；从任务配置启动时位于对应运行目录的 `login/`。停止配置会取消正在等待的登录子进程。


### 暖色 Mac 风格工作区

中控使用顶部导航、米白背景和棕金色控件。模拟器卡片显示已采集的角色头像与任务摘要；开关机仍在卡片右上角，小人只根据配置是否在执行来运动或睡觉。任务配置页左侧为已保存方案，右侧为五类任务；点击任务仅查看说明；拖动图标可跨分类移动，并可在分类内调整顺序。分类与顺序保存在 `.web-data/task-layout.json`，刷新或重启中控后保留，也会同步到方案编辑器的任务库。已有方案的任务与执行顺序不随分类变化。也可聚焦任务图标，使用 `Alt+左右方向键` 切换分类、`Alt+上下方向键` 调整顺序。

快捷操作：macOS 使用 `⌘K` 打开快速导航，Windows 使用 `Ctrl+K`；输入页面或实例名称，用方向键选择、回车打开。`⌘1–5` / `Ctrl+1–5` 在五个页面间切换。编辑任务配置时可用 `⌘S` / `Ctrl+S` 保存，`Esc` 关闭当前弹窗。编辑弹窗保留明确的取消和保存按钮，日志、截图等只读弹窗支持点击背景关闭。


### 从任务方案发送到实例

在任务工作区的方案卡片点击“发送到实例”，选择一个或多个实例后确认。列表会显示实例当前方案，并支持全选可用实例。发送会绑定所选方案，之后在模拟器卡片点击“启动配置”执行；发送本身不启动游戏或任务。仅已开机、ADB 已连接、游戏在前台且已确认进入游戏主界面的实例可接收；执行配置、开关机或采集中的实例不可接收。列表每 5 秒进行一次只读状态检查，发送时后端再次实时校验并在写入前检查忙碌状态。不可用的实例会置灰、取消勾选并显示具体原因，全选仅选择已就绪的实例。部分实例发送失败时会显示原因，成功的实例不受影响。实例卡片中的手动配置预设入口仍可用于开机前准备，独立于“发送到实例”的就绪检查。
